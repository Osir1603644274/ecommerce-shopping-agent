# 商品知识库、MCP与比较工具：本地功能验收

结论：`BOUNDED_FUNCTIONAL_ACCEPT`。本地实验能力已完成；不代表知识全覆盖、人工质量评审通过或生产性能排名可用。通用功能默认开关仍关闭，本地Demo显式开启。

## 数据与实现

- 439件标题审核：明确288、冲突50、歧义89、未知12。CLEAR是标题声明明确，非实物鉴定、非人工金标。171型号组均有来源调查记录。
- 425条事实、111个来源，覆盖99/171型号、199/439商品；72型号尚无可收录事实。字段为芯片97、电池67、相机规格85、充电83、屏幕85、续航实测8；游戏/拍照实测均为0。
- 快照`phone-v2-081e5e82a58e`：[覆盖表](../../../datasets/knowledge/phone-v2/COVERAGE.md)、数据审计（本地材料：`data-audit-final.json`）。保留旧V1和原5条续航事实/8个来源回执，不覆盖冻结数据。
- 公开购物工具为search_products、get_product_details、search_product_evidence、compare_products；旧rerank_products_in_scope保留兼容。指定比较和范围比较共用核验与父模型表达。
- 型号过滤、字段查询、BM25/BGE与RRF均运行。购物端真实HTTP MCP；Codex实查同一证据及版本。服务只读，不开放订单、记忆或写入。
- 原检索query随服务端CandidateScope保存，后续比较保留指定型号、候选ID、任务版本和硬条件。大整数ID交给模型时用字符串。未知型号不绑定事实；服务故障仅返回商品事实与明确不可用提示。
- 父模型复用既有预算/追踪，引用绑定型号和地区；事实从库中渲染，取舍标为推断。程序显示模拟参考价和真实缺口，不发布模型编造的覆盖数量。

## 可用边界与后续问题

1. 能做规格解释、有限续航证据展示、条件核验与有依据的待核验建议。没有游戏/拍照实测，不能声称已经能可靠排序实际游戏或成像性能。地区未知、软件/亮度未知继续保留。
2. 21轮中3轮保守回退，开发8轮中5轮保守回退。部分回退仍提供事实和来源，但父模型没有生成可发布的完整取舍。效果并非全面优于旧模式。
3. 父模型的“像素配置更高”等概括可能超出本轮完整可比证据，语义解释仍须复核。已有引用核验和保守边界不能代替逐句蕴含判定；不宣称零幻觉、人工质量ACCEPT或生产排名授权。
4. 多个商品同型号会重复展示资料；精确型号检索仍可能被长Query中的场景词稀释。这两项列为后续改进，不扩充商品库、不启动训练。
5. 72型号缺事实，所有型号的游戏/拍照实测缺口按覆盖表继续管理。本轮完成有边界的全量调查，不把未取得材料说成已经穷尽网络资料。
