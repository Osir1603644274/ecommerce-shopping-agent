# 聊天界面与正文流式输出验收

实施：2026-09-15—16（本机）。这是功能与回归验收，不是生产容量或多机高可用证明。

## 实际变化

- 原 SSE 仅传执行进度；现在正文读取模型 `stream=True` 的 `delta.content`，通过 `answer_delta` 传给浏览器。没有将完整答案切片后延时播放。
- 已核验资料先冻结，再进行独立的展示文案生成。GraphV2 原答案、签名回执与交易权限边界不改写；新增展示生成会增加一次只读模型调用，不宣称原有完整链路首字即可返回。
- 展示记录绑定 runId、requestId、证据摘要、增量序号与正文摘要。Redis 保存当前前缀，归档另存 `answer_stream` 记录；不公开模型推理、工具参数或登录凭证。
- 连续模式、全目录导购、二手手机导购及商品追问接入正文增量。单步调试仍控制安全阶段；旧手机单步模式保留原完成回执，不承诺每个内部阶段均有文字流。
- 浅色历史侧栏、居中聊天、底部输入框；Enter 发送、Shift+Enter 换行、输入法组合输入保护、发送后即时显示用户消息。生成中保留草稿编辑与停止按钮；离开底部阅读时不强制滚动。
- 商品与交易、Java 后端学习详情改为按需打开的抽屉。收藏、订单、优惠入口保留；抽屉关闭不关闭已启用的后台记录。手机侧栏可关闭。

## 停止、继续和断线的区别

1. **断线**：只重新订阅同一 run，首帧恢复已有前缀，增量按序号去重；不会自动重发导购或交易请求。
2. **停止**：请求服务端安全暂停。文案生成时关闭模型流并保存已收到前缀；工具执行时仍等待其安全检查点，不能撤销已经提交的数据库事务。
3. **继续**：使用相同证据和前缀发起新的只读续写调用，不重复搜索或交易。这不是模型 KV 状态的逐 token 原地恢复。
4. **结束本轮**：保留已生成文字和历史记录，然后允许新问题。历史侧栏可回看归档；旧历史为只读，不伪装为能够恢复任意旧引擎会话。

## 本轮修复的回归

- 新的 `:answer` 记录必须在同一工作区持锁任务内写入，不绕过锁校验。
- 停止请求等待短时增量写锁；同一 run 的重复暂停幂等，阶段 revision 前进不丢失用户停止意图。
- 登录过期时恢复本次未成功提交的草稿；旧账户延迟回包不能重新显示旧内容。
- 抽屉组件保持后端记录器生命周期，关闭界面不清空记录开关。
