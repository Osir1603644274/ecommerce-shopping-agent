## 1. 已确认的目标

1. 知识库解决的问题由实际 Query、现有证据和失败记录决定，不预设洗护、兼容性等内容一定有需求。
2. 首批调查手机、服饰、运动鞋，不要求等量建设。
3. 先改善购物回答，再完成 Codex 真实使用；最终电商 Agent 和 Codex 均通过 MCP 查询同一知识服务。
4. 第一版回答中不自动联网补答案。离线资料整理与回答时联网是不同流程。
5. 知识效果与 MCP 接入能力分开验收，记录真实问题、修复和数据，不借接入协议宣称回答质量提升。

## 6. 由数据推导的实施顺序

以下是审计后的建议，不是已完成实现或未经验证的效果承诺。

1. **来源与实体可行性核查**：针对上表具体 Query 查资料，登记可回答的事实、适用对象、来源和缺口。手机先精确型号功能/尺寸及芯片相机资料；服饰先术语解释；跑鞋先结构/用途说明。游戏/拍照好坏与单机续航结论需要进一步实测依据，不能只用规格替代。
2. **整理小批知识与证据合同**：明确区分品类通识、型号事实、卖家声明、机况/库存；事实查询与段落检索共用证据 ID，处理未知和冲突。身份不明时允许给通识，禁止给具体商品背书。
3. **补多品类购物合同，再接购物 Agent**：服饰/跑鞋先明确现有商品字段与可支持约束；沿 MCP 查询知识，在回答中解释和引用。第一轮不让尚未验证的知识改写硬过滤、库存或付款状态。
4. **独立质量验证**：当前已读 Query 用于开发；另准备未见问题，分别测检索证据、结论支持、拒答/澄清和运行错误。对照同一模型/相同商品候选，不靠增加预算或更换模型制造提升。预先确认门槛后再运行正式实验。
5. **Codex 真实接入**：同一知识服务的 MCP 接口，完成实际问题→调用→查看证据→引用；测协议发现、结果完整性、未知/冲突和断连处理。购物端和 Codex 均经 MCP；Skill 非必需。

暂不优先：无需求证据支持的完整洗护百科；所有服饰/鞋款官方资料的自动关联；主观穿搭标准答案库；实时销量/价格库存；从公开型号资料推断具体二手机况；无条件自动联网入库。
